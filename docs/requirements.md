# 島根ARアプリ 要件定義書

最終更新: 2026-09-21 / 本番: 2026年10月上旬 / 体制: 2名（歩武=開発、じん=アセット）

自作ポスターにスマホのカメラをかざすと、画面の中に3Dモデルが出てくるWebアプリを作り、文化祭で展示する。
来場者はインストール不要で、QRコードからURLを開くだけで体験できる。

---

## 1. 目標

**来場者が足を止めて、自分のスマホで試してくれること**をゴールとする。

見てもらうだけなら動画で十分。ARにする意味は「自分の手でカメラを動かして、自分で発見する」体験にあるので、そこを崩さない。

成功条件:

1. **説明なしで使える** — QRを読んでからARが出るまで、口頭のフォローなしで到達できる
2. **その場で壊れない** — 文化祭の時間帯中、機種を選ばずに動き続ける
3. **今後使える型を残す** — モデルとポスターを差し替えるだけで使い回せる状態にしておく

モデルのクオリティの高さは目標に入れない。スマホの小さい画面で手ぶれしながら見るので精密さは伝わらない。
**ちゃんと認識されて、すぐ出て、カクカクしない**方が体験の質に直結する。

---

## 2. MVP

**ポスター1枚にかざすと、3Dモデルが1体出てくる。それが公開URLで、人のスマホで動く。**

これが成立した時点で展示としては成立する。残りは全て加点要素。

- [ ] スマホでURLを開くと、カメラ許可を聞かれて映像が出る
- [ ] 自作ポスターにかざすと、3Dモデルが1体表示される
- [ ] スマホを動かしても、モデルがポスターについてくる
- [ ] iPhone（Safari）とAndroid（Chrome）の両方で動く
- [ ] 初回読み込み中に「読み込み中」の表示が出る（無反応に見えない）
- [ ] Vercelの公開URLと、それを指すQRコードがある

### 加点要素（MVPが全部終わってから着手）

- [ ] マーカー・モデルを複数対応する
- [ ] モデルが回転や上下などの簡単な動きをする
- [ ] 効果音やBGMをつける
- [ ] スクリーンショットボタンをつける

---

## 3. やらないこと

14日間に収めるため、以下は最初から捨てる。

| やらないこと | 理由 |
| --- | --- |
| ログイン・ユーザー登録 | 個人情報を扱う責任が発生する。展示には不要 |
| スコア・スタンプのサーバー保存 | バックエンドが必要になり、規模が一気に増える |
| 複数人で同じARを共有 | リアルタイム通信が必要。期間的に無理 |
| キャラクターの本格的なアニメーション | リグ（骨）を入れる作業が重い。平易な回転・上下で代用する |
| スマホアプリ（App Store等）化 | 審査に時間がかかる。WebならQRで即配布できる |
| マーカーなしのAR（床に置くタイプ） | iPhoneで動かない。来場者の半分が体験できなくなる |

判断基準: **「これがないと来場者が3Dモデルを見られないか？」で考えて、No なら後回し。**

## 4. 技術構成

**モデルの形式は `.glb` に統一する。**

これが重要なのは、モデルの出所を問わなくなるため。フリー素材でも、AI生成でも、Blenderで自作しても、
最終的にglbになっていればアプリ側はそのまま読み込める。**調達方法を途中で変えても、コードの書き直しは発生しない。**

| 層 | 使うもの | 役割 |
| --- | --- | --- |
| AR認識 | MindAR 1.2.5 | カメラ映像からポスターを見つけて、位置を計算する |
| 3D描画 | Three.js 0.169.0 | glbを読み込んで画面に描く |
| ビルド | Vite + TypeScript | 開発サーバーと本番用ビルド |
| 公開 | Vercel | HTTPS付きのURLを自動で発行 |
| モデル形式 | `.glb` | 上記の通り、これに統一 |

## 5. 必要な依存

### インストール

```bash
cd Shimane-AR-app
npm ci
```

`.npmrc` に `ignore-scripts=true` を置いてあるので、オプションは不要。
この設定が無いと canvas のビルドで必ず失敗する（下記「canvasのビルドエラー」を参照）。

### 一覧

| パッケージ | バージョン | 区分 | 役割 |
| --- | --- | --- | --- |
| `mind-ar` | `1.2.5` | dependencies | 画像認識AR本体 |
| `three` | `0.161.0`（完全固定） | dependencies | 3D描画エンジン |
| `@types/three` | `0.161.0` | devDependencies | TypeScript型定義 |
| `vite` | `^8.3.0` | devDependencies | 導入済み |
| `typescript` | `~6.0.2` | devDependencies | 導入済み |

### バージョン指定の注意点

**`three` には `^` を付けない。`0.161.0` で完全固定する。これは実測で決めた値。**

MindAR 1.2.5 は `sRGBEncoding` という定数を three から import しているが、
これは **three 0.162.0 で削除された**。0.162 以上を入れるとビルドが必ず失敗する。

```
[MISSING_EXPORT] "sRGBEncoding" is not exported by "three/build/three.module.js"
```

各バージョンを実際に調べた結果、`sRGBEncoding` を export する最終版が **0.161.0** だった。
MindAR 1.2.5 のリリースが2024年1月で、当時の three が 0.160 台だったことと一致する。

| three | `sRGBEncoding` |
| --- | --- |
| 0.160.1 | export あり |
| **0.161.0** | **export あり（最終）** |
| 0.162.0 以降 | 削除済み |

なお、この不整合は **TypeScript の型チェックでは検出できない**（tsc は three の export 一覧までは見ない）。
検出したのはバンドラ（Rollup）で、`npm run build` の後半で初めて止まる。

**`@types/three` は `three` と同じ `0.161.0` に揃える。**

`three` は型定義を同梱していないため別途必要。バージョンを指定しないと最新が入り、本体と型がズレる。

### 補足: mind-ar には型定義がない

TypeScript から import するとエラーになるため、以下の宣言ファイルを作る。

`Shimane-AR-app/src/mind-ar.d.ts`:

```ts
declare module 'mind-ar/dist/mindar-image-three.prod.js';
```

### import の書き方

```ts
import { MindARThree } from 'mind-ar/dist/mindar-image-three.prod.js';
import * as THREE from 'three';
import { GLTFLoader } from 'three/examples/jsm/loaders/GLTFLoader.js';
```

### ローカルHTTPSと実機テスト

カメラを使うWebアプリは、セキュアな接続でないとブラウザがカメラを許可しない。
正確には `navigator.mediaDevices` 自体が存在しなくなる。

| アクセス先 | セキュア | カメラ |
| --- | --- | --- |
| `https://` 全般 | ○ | 使える |
| `http://localhost` | ○（例外扱い） | 使える |
| `http://192.168.x.x` | × | **使えない** |

**PCでの開発に証明書は不要。** `localhost` は例外的にセキュア扱いなので、そのまま動く。

**スマホでの確認には正式なHTTPSが必要。** 自己署名証明書でもLAN経由で試せるが、
「発行元が未信頼」の警告が必ず出る。これは証明書をどう作っても消えない（第三者の保証が無いため）。
そのため **実機確認は Vercel のプレビューURLで行う**方針とする。

なお LAN経由を試す場合は `npm run cert` で証明書を作ってから `npm run dev` する。
証明書のSANには **`IP:` としてLAN内アドレスを入れる必要がある**（`DNS:` では
ブラウザが認めない）。`scripts/gen-cert.mjs` が自動で検出して入れる。
Wi-Fiを変えてIPが変わったら作り直すこと。

### マーカーのコンパイル

ポスター画像はそのままでは使えず、MindAR用の `.mind` ファイルに変換する必要がある。

1. [MindAR Image Compiler](https://hiukim.github.io/mind-ar-js-doc/tools/compile) にポスター画像をアップロード
2. 出力された `targets.mind` をダウンロード
3. `Shimane-AR-app/public/targets.mind` に配置

ポスターのデザインを変更したら、**毎回コンパイルし直す必要がある**。

### 既知のリスク

| リスク | 内容 | 対策 |
| --- | --- | --- |
| 初回ロードが重い | MindARは内部でTensorFlow.jsを使っており、それだけで数MBある | glbのファイルサイズ削減（§6）、ローディング表示 |
| MindARが更新停止 | 2024年1月が最終更新。将来のブラウザ更新で壊れる可能性 | 今回の展示期間中は問題なし。バージョン固定で対応 |
| 印刷物での認識率低下 | 画面で見た時と、印刷した時で認識率が変わる | Day 13 に印刷物での実地テストを必ず行う |

### canvasのビルドエラー

`--ignore-scripts` なしで `npm install` すると、以下のエラーで必ず止まる。

```
fatal error: 'exception' file not found
gyp ERR! build error
npm error node-pre-gyp ERR! not ok
```

**原因**: MindAR が `canvas@^2.10.2` に依存している。これはC++で書かれたネイティブモジュールで、
インストール時にコンパイルが走る。しかし canvas 2.x は2022年時点のパッケージで、
現在のmacOS SDKではコンパイルが通らない。Xcode Command Line Tools が入っていても直らない。

**なぜ無視してよいか**: `canvas` は Node.js 側で画像を処理するためのもので、
MindAR ではマーカーのコンパイルツールを**コマンドラインで動かす場合にのみ**使われる。
今回はマーカーを [Webのコンパイラ](https://hiukim.github.io/mind-ar-js-doc/tools/compile) で作るので、
ブラウザで動くコードからは一切呼ばれない。入っていなくても動作に影響しない。

**対処**: `Shimane-AR-app/.npmrc` に `ignore-scripts=true` を置いてある。
これによりローカルでも Vercel でも、インストール時のスクリプトが走らなくなる。

**副作用**: 他のパッケージのセットアップも飛ぶ。ただし現構成（vite 8 / esbuild 0.28）では
プラットフォーム別パッケージ方式のため postinstall に依存しておらず、
`node_modules` を消してからの `npm ci` → `npm run build` 成功を確認済み。

## 6. 【じん担当】アセット準備

ミッションは **「スマホでサクッと表示できるglbファイル」を揃えること**。

モデルをゼロから作る必要はない。むしろ**作らないで済む方法を探すのが仕事**。
自作は、探しても見つからなかったものだけでいい。

### 作業の流れ

```
探す or 生成 → glbに変換 → Blenderで軽量化 → チェック → 共有フォルダに納品
```

### 6.1 どこで探すか

上から順に試す。上のほど楽。

| 場所 | 種類 | ライセンス | 向いているもの |
| --- | --- | --- | --- |
| [Poly Pizza](https://poly.pizza/) | フリー素材 | CC0 / CC-BY | ローポリの小物・建物。glb直DL可 |
| [Quaternius](https://quaternius.com/) | フリー素材 | CC0 | ゲーム風モデル。シリーズで統一感が出せる |
| [Kenney](https://kenney.nl/assets) | フリー素材 | CC0 | 超軽量。背景・装飾に最適 |
| [Sketchfab](https://sketchfab.com/) | フリー素材 | 要確認 | 数が圧倒的。ただし重いモデルが多い |
| Meshy / Tripo | AI生成 | 要規約確認 | 探してもないオリジナルの物体 |
| Blender自作 | 自作 | — | 上記全部でダメだったものだけ |

**AI生成の注意点**: 現状、面・建物・食べ物などの**静物は実用レベル**だが、
**人型キャラクターは苦手**（形が崩れやすく、動かせない）。キャラを作るならフリー素材を探す方が確実。

### 6.2 ライセンスのルール

ここは省略不可。文化祭とはいえ公開するので、規約違反はトラブルになる。

- **CC0** — どう使ってもOK。表記も不要。一番楽
- **CC-BY** — 使ってOK。ただし**作者名の表示が必須**
- **CC-BY-NC / 商用不可** — 文化祭で別途お金を取らなければ基本OK。心配なら避ける
- **ライセンス不明** — **使わない**。判断に迷ったら使わないで、歩武に相談

ダウンロードしたらすぐに、**モデル名・作者名・URL・ライセンスをメモする**。
後から思い出すのはほぼ不可能。アプリ内にクレジット画面を作るので、そこに載せる。

### 6.3 納品の基準

| 項目 | 基準 | なぜ |
| --- | --- | --- |
| 形式 | `.glb`（1ファイルにまとまっていること） | アプリが読める唯一の形式 |
| ファイルサイズ | **5MB以下**（理想は2MB以下） | 会場Wi-Fiでの読み込み時間 |
| ポリゴン数 | 5万以下 | スマホでカクカクしないため |
| テクスチャ | 1024px以下、枚数は少なく | サイズの大半は画像が原因 |
| 向き | Z軸が正面、原点に足元が来ている | 表示位置の調整が楽になる |
| ファイル名 | 半角英数字とハイフン。例 `oni-statue.glb` | 日本語名はエラーの原因になる |

**サイズが大きいときの削り方**（効果の大きい順）:

1. テクスチャ画像を4096pxやその下から1024pxに縮める — これだけで数分の一になることが多い
2. Blenderの **Decimate モディファイア**でポリゴンを減らす
3. 見えない部分（物体の内側、底面）のメッシュを削除
4. 使っていないマテリアルやアニメーションを削除

### 6.4 チェック方法

納品前に必ず、[glTF Viewer](https://gltf-viewer.donmccurdy.com/) にglbをドラッグして確認する。
ここで正しく見えないものは、**アプリでも確実に見えない**。

見るべきポイント:

- 真っ黒・真っ白になっていないか（テクスチャが外れている）
- 裏側が透けていないか
- 向きと大きさが変でないか

### 6.5 ポスターをつくるときのコツ

ポスターは**カメラが覚える目印**になるので、デザインが認識率に直接影響する。

- **良い**: 絵柄が細かく複雑、色の差がはっきり、非対称
- **悪い**: 単色の背景が広い、ゆるいグラデーションだけ、左右対称、同じ模様の繰り返し
- **印刷**: 光沢のある紙は照明が写り込んで認識を邪魔する。**マット紙推奨**

## 7. フェーズと日程

4つのフェーズに分ける。各フェーズの末尾に「これができてないと次に進めない」関門を置く。

```
Phase 1 土台づくり  Day 1-3
Phase 2 中身を入れる Day 4-9
Phase 3 仕上げ      Day 10-12
Phase 4 本番準備    Day 13-14
```

### Phase 1: 土台づくり（Day 1-3）

目的は**リスクを潰すこと**。クオリティはさておき、「自分たちの環境でARが本当に動くのか」を最初に確かめる。

| Day | 歩武（アプリ） | じん（アセット） |
| --- | --- | --- |
| 1 | MindAR + Three.jsを導入し、サンプルが動くところまで | 環境準備（Blenderとアカウント）、素材サイトを一通り見る |
| 2 | 実機（iPhone/Android）でカメラが動くことを確認 | テスト用のglbを1個探してくる |
| 3 | テスト用glbを表示させる **← 関門** | テーマ決定のための案出し |

> **関門**: Day 3終了時点で、実機でポスターにかざすと何かが出る状態。ここで詰まったら、方式を見直す。

### Phase 2: 中身を入れる（Day 4-9）

テーマを確定させ、本番用のポスターとモデルを揃える。ここが一番手を動かす期間。

| Day | 歩武（アプリ） | じん（アセット） |
| --- | --- | --- |
| 4 | テーマ確定の話し合い。必要モデルのリスト化 | 同左 |
| 5-6 | ポスター画像をマーカー登録する仕組み | モデルの探索・生成・選定 |
| 7-8 | 読み込み中の表示、モデルの位置・サイズ調整 | glbの最適化と納品 |
| 9 | 本番モデルを組み込んで実機確認 **← 関門** | ポスターデザインの仕上げ |

> **関門**: Day 9終了時点でMVP完了。ここを超えたら、以降は全部加点。

### Phase 3: 仕上げ（Day 10-12）

| Day | やること |
| --- | --- |
| 10 | Vercelに公開し、本番と同じURLで実機確認 |
| 11 | 読み込み速度の改善。複数マーカー対応（余裕があれば） |
| 12 | 他の人のスマホを借りてテスト。機種差の確認 |

### Phase 4: 本番準備（Day 13-14）

| Day | やること |
| --- | --- |
| 13 | ポスター印刷、QRコード作成、**印刷物での認識テスト** |
| 14 | 会場での設営リハーサル。バッファ日 |

> 画面で見たポスターと、**印刷したポスターは認識率が違う**（紙質の反射や印刷の発色のせい）。
> Day 13 の印刷テストは飛ばさないこと。

## 8. まだ決まっていないこと

一番大きい未決事項は**展示のテーマ**。これが決まらないと、じんのDay 5以降が動けない。

| 決めること | 期限 | 現時点の状態 |
| --- | --- | --- |
| 展示のテーマ | Day 4 | 未定。神話系・観光名所・学科紹介が候補 |
| モデルは何体必要か | Day 4 | テーマ次第。まず1体、最大3体までを想定 |
| 本番日の正確な日付 | Day 3 まで | 「10月上旬」としか分かっていない |
| 配布カードを作るか | Day 13 | 未定。印刷予算次第 |
| 印刷予算 | Day 13 まで | 未確認 |

### テーマを決めるときの判断軸

テーマは「面白そうか」だけではなく、**モデルが手に入るか**で選ぶ。この期間ではそこがボトルネックになる。

- **建物・景色・道具** → フリー素材もAI生成も強い。**楽**
- **動物・デフォルメした生き物** → フリー素材がそこそこある。**中くらい**
- **特定の人物・オリジナルキャラ** → 探してもない。自作か、似たもので代用。**大変**
