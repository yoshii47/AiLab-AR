# アセット制作ガイド【じん担当】

最終更新: 2026-10-07 / 対象: AI生成でモデルとポスターを作る人

要件定義書 `requirements.md` §6 の実務版。実際にアプリを動かして分かったことを反映している。

---

## 0. 先に知っておくこと

**ファイルの要件は、AI生成のプロンプトには書かない。**

「5MB以下」「ポリゴン5万以下」といった条件を生成ツールに打ち込んでも効きません。
AIが読むのは**見た目の説明だけ**です。ファイルの条件は、

- 生成ツールの**書き出し設定**で選ぶ
- 書き出した後に**Blenderで調整する**

のどちらかで満たします。なので、この資料は

1. **プロンプト**（AIに打ち込む文章）
2. **納品チェック**（書き出した後に確認すること）

の2段階に分かれています。

## 1. 3Dモデルのプロンプト

### テンプレート

英語の方が精度が出ます。`[ ]` の部分だけ差し替えてください。

```
[作りたいもの], low-poly 3D game asset, single centered object,
clean simple geometry, flat matte colors, soft neutral lighting,
no background, no ground plane, upright, facing forward, full object visible
```

**例:**

```
a cute shiba inu dog sitting, low-poly 3D game asset, single centered object,
clean simple geometry, flat matte colors, soft neutral lighting,
no background, no ground plane, upright, facing forward, full object visible
```

### 後半の呪文が何をしているか

消さないでください。それぞれ理由があります。

| 語句 | 効果 |
| --- | --- |
| `low-poly` / `clean simple geometry` | ポリゴン数とファイルサイズを抑える。スマホで動かすため |
| `single centered object` | 複数の物が生成されるのを防ぐ |
| `flat matte colors` | テクスチャが軽くなる。光沢は実機で汚く見えがち |
| `no background` / `no ground plane` | 背景の板や地面が一緒に生成されるのを防ぐ |
| `upright, facing forward` | 向きを揃える。横倒しで出てくる事故が減る |
| `soft neutral lighting` | テクスチャに影が焼き付くのを防ぐ。アプリ側で照明を当てるため |

### AIが苦手なもの（避ける）

| 苦手 | どうする |
| --- | --- |
| **文字・ロゴ・記号** | 絶対に崩れる。文字が要るならポスター側に入れる |
| **人間・顔** | 形が崩れやすい。動物やデフォルメなら成功率が上がる |
| **細い棒・ワイヤー・網** | 溶けるか消える。太めの形に言い換える |
| **ガラス・水・透明なもの** | 真っ黒か真っ白になりがち |
| **左右対称で特徴のないもの** | 出るには出るが面白くない |

得意なのは **建物・道具・食べ物・デフォルメした生き物**です。テーマ決めの段階でここに寄せると楽になります。

### 書き出し設定

- 形式: **GLB**（GLTFではなくGLB。1ファイルにまとまる方）
- 品質/ポリゴン: 選べるなら**低い方**から試す。足りなければ上げる
- テクスチャ解像度: 選べるなら **1024px**

## 2. モデルの納品チェック

[glTF Viewer](https://gltf-viewer.donmccurdy.com/) にドラッグして確認。**ここで変なものはアプリでも必ず変です。**

### 必須（守らないと動かない・見えない）

| 項目 | 基準 |
| --- | --- |
| 形式 | `.glb` 単体。`.gltf` + 別ファイル群は不可 |
| ファイルサイズ | **5MB以下**。理想は2MB以下 |
| ポリゴン数 | 5万以下 |
| テクスチャ | **1024px以下**、枚数は少なく |
| ファイル名 | 半角英数字とハイフン。例 `shiba-inu.glb`。日本語・スペース不可 |
| **向き** | **Y軸が上、Z軸が正面** |
| 見た目 | 真っ黒／真っ白でない。裏側が透けていない |

**向きだけは要注意です。**アプリはモデルを「Y軸が上」と想定して立ち上げます。Z軸が上のまま書き出す
ツールもあるので、Blenderで確認してください。横倒しや逆立ちで表示されたらこれが原因です。

### 気にしなくていいもの

以前「原点に足元を合わせる」「大きさを揃える」とお願いしていましたが、**アプリ側で自動補正するように
直したので不要になりました。**原点が隅にあっても、サイズが1000倍でも、正しく表示されます。
向きだけは自動補正できないので、そこだけお願いします。

### サイズが大きいときの削り方（効果の大きい順）

1. **テクスチャを1024pxに縮める** — これだけで数分の一になることが多い
2. Blenderの **Decimate モディファイア**でポリゴンを減らす
3. 見えない部分（物体の内側、底面）のメッシュを削除
4. 使っていないマテリアル・アニメーションを削除

## 3. アニメーション

**アニメーション入りのglbは、そのまま渡してくれれば自動で再生されます。**アプリ側の対応は済んでいます。

- ボーン（リグ）があってもなくても再生される
- **ループする動き**にすること。始点と終点がつながっていないとカクッとなる
- 複数のアニメーションが入っていると**全部同時に再生**される。1つに絞るのが安全
- 激しすぎる動きは、ARだと画面外に出ていく。**その場で完結する動き**にする

AI生成ツールでアニメーションが付けられるなら、泳ぐ・揺れる・回るといった**単純な繰り返し**が向いています。

## 4. ポスター（マーカー画像）

ここはモデルとは別の話で、**認識率に直結します。**アプリがポスターを見つけられるかどうかが決まります。

### 必須

| 項目 | 基準 | 理由 |
| --- | --- | --- |
| **背景を透過にしない** | **白などで塗りつぶして書き出す** | 透過PNGは真っ黒として処理され、**まず認識しません** |
| 余白を詰める | 絵柄が画面いっぱいに来るように | 余白が広いほど目印が減る |
| 形式 | PNG または JPG | |

**透過の件は実際に起きた事故です。**見た目は白背景でも、データ上が透明だとアプリ側では黒になります。
Illustrator や Figma から書き出すとき、背景のチェックを外さないでください。

### 認識しやすいデザイン

**グレースケールにしても成立するか**で判断してください。アプリは色を捨てて明暗だけを見ています。

| 良い | 悪い |
| --- | --- |
| 絵柄が細かく複雑 | 単色の背景が広い |
| **明るさの差**がはっきり | 色は違うが明るさが同じ（例: 同じ濃さの赤と緑） |
| 左右非対称 | 左右対称 |
| 模様がそれぞれ違う | 同じ模様の繰り返し |

> 「色の差」ではなく **「明るさの差」** です。ここを間違えると、鮮やかなのに認識しないポスターができます。

### 印刷

- **マット紙**を使う。光沢紙は照明が反射して認識を邪魔する
- 画面で見たときと印刷したときで認識率が変わるので、**必ず印刷して試す**

## 5. 納品物

1つの展示につき、この3点をセットで渡してください。

```
1. モデル          xxx.glb
2. ポスター画像    xxx.png（透過なし・余白を詰めたもの）
3. 出典メモ        下記
```

### 出典メモ（必須）

**ダウンロードした直後に書いてください。**後から思い出すのはほぼ不可能です。

```
モデル名:
作者名:
入手URL:
ライセンス: CC0 / CC-BY / その他（    ）
```

- **CC0** — 自由に使える。表記も不要。一番楽
- **CC-BY** — 使えるが**作者名の表示が必須**
- **ライセンス不明** — **使わない**。迷ったら歩武に相談

AI生成の場合も、**使ったツール名と、そのツールの規約で商用利用・Web公開が可能か**をメモしてください。

> このアプリは Vercel で**インターネットに公開**します。校内展示ではなく世界中から見られる状態なので、
> 「Web公開と再配布が許されているか」が判断の分かれ目になります。
